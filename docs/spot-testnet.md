# Spot trading

Set `NEXT_PUBLIC_STELLAR_NETWORK=mainnet` or `testnet` to choose the app and wallet default. Unset values default to Testnet; other values fail configuration validation. Spot executes on Mainnet, independently of the app default. Native Stellar AMM / order book quotes remain usable when the sibling API is unavailable. Its Soroban quotes are compared by net output when available. Selecting a quote updates the receive amount and review. Each Soroban route exposes its protocols, pool hops, split allocations, fees, minimum received, price impact and expiry.

The browser uses relative `/api/spot/quotes` and `/api/spot/swaps/record` URLs. Both Next.js handlers resolve their backend at request time from `LUMIX_API_URL`, then `API_URL`, then `http://127.0.0.1:8080`. Trailing slashes and an optional backend path prefix are handled consistently. `GET /api/spot/quotes` exposes only whether this URL is valid, not the private URL. The sibling API and its quote worker must be running for Soroban quotes. Its response currently identifies `meta.network: "pubnet"`. `NEXT_PUBLIC_STELLAR_HORIZON_URL`, `NEXT_PUBLIC_STELLAR_RPC_URL`, `NEXT_PUBLIC_STELLAR_EXPLORER_URL`, USDC issuer and SAC values must match the selected deployment network. `NEXT_PUBLIC_STELLAR_MAINNET_RPC_URL` optionally overrides Mainnet RPC when the app defaults to Testnet. Perpetuals demo payments remain Testnet-only.

## Port-independent API routing

The frontend listener is independent of the backend address. Export `PORT` in the shell before `npm run dev` or `npm start`, or pass `-- -p <port>`. Next.js does not load the listener port from `.env` files. Docker and Compose default to port 3002 and allow overriding `PORT`; the published and container ports stay aligned.

Behind Nginx, proxy the frontend domain, such as `app.lumixmarket.com`, to the chosen frontend listener and include `/api/` paths. The browser stays on that domain for all Lumix API requests. It never contacts the backend directly, so changing the frontend port or using HTTPS externally with an internal HTTP API does not require browser CORS changes.

Set `LUMIX_API_URL` or `API_URL` to the API container/service URL in Docker, not the frontend domain or the frontend container's loopback address. These server-only values can change at runtime without rebuilding the browser bundle. Spot no longer needs `NEXT_PUBLIC_API_URL`. Public Blux/Stellar configuration still requires a rebuild.

Swap reporting forwards only validated JSON to `/v1/spot/swaps/record`, preserves its 202 response (including an empty body), and never forwards browser cookies or authorization. It remains fire-and-forget after network acceptance, with confirmation recovery and duplicate protection. Reporting failure does not delay success or balance refresh.

Browser harnesses require their suite-specific base URL, `LUMIX_TEST_ORIGIN`, or a shell-exported `PORT`; they no longer assume a frontend port. For example, set `LUMIX_TEST_ORIGIN=http://localhost:3002` when testing a server listening there. Run `npm run build` before `npm run test:proxy:browser`: that suite starts isolated production frontends on port 3002 and an OS-selected port, with a disposable upstream that deliberately sends no CORS headers. `PROXY_TEST_PORTS` can override those test listener ports. No funded transaction or real ingestion service is used.

Spot uses `@bluxcc/react` as its only Blux dependency. Native routes recheck the selected path and build the reviewed path payment. Soroban routes encode the selected API quote's `txData` using the deployed contract ABI and simulate it, targeting the API-configured Lumix aggregator. Transaction construction uses `StellarSdk` exported by Blux React. Both routes inspect the envelope, sign through `useBlux().signTransaction`, verify the signed body and network signature, then submit without patching SDK files. Checks bind the simulated call to the reviewed sender, aggregator, function and arguments, enforce expiry and a 1 XLM Soroban fee cap, and retain the signed hash for confirmation recovery without automatic resubmission. This cap is a maximum, not an estimated network fee.

Soroban routes require an existing authorized receiving trustline with enough capacity. Native routes add or increase the receiving trustline automatically. Quotes refresh every 30 seconds; changing assets, amount, wallet or slippage invalidates the API selection. Expired Soroban candidates disappear and a previously selected unavailable quote must be selected again.

## Native Stellar routing

Spot uses the existing app-level Blux setup and calls its React hooks directly:

- `spot-workspace.tsx`: `useStrictSendPaths` and `useAssets`, plus quote selection and wallet review. `spot-execution.ts` constructs, checks, signs and submits swaps using the public Blux React API. A strict cached Horizon account read supplies balances, liabilities and reserves; this avoids the installed SDK's swallowed account errors.
- `spot-asset-selector.tsx`: one debounced, cursor-paginated search field backed by `useAssets`; search by code, known metadata name, full issuer or `CODE:ISSUER`. Rows show six issuer characters on either side of an ellipsis; full identities remain in discovery, accessible labels and transactions.
- `spot-utils.ts`: exact amounts, full asset identities, reserve/fee validation, Testnet checks and final-envelope checks.
- `spot-token-icon.tsx`: exact local artwork, optional issuer-published images and a resilient fallback, using the existing query cache.

There is no Spot provider, bridge, asset seeder or custom routing engine. Native XLM, verified Circle Testnet USDC and Circle Testnet EURC are the supplied choices; connected-account and discovered classic assets remain available. Development assets are not supplied. Asset existence does not imply executable liquidity.

## Token artwork

`components/spot-token-images.json` records the network, full issuer, image path, publisher and download URL for 30 genuine artworks in `public/tokens/stellar`. The collection contains native XLM and 29 existing Mainnet-issued assets selected from Stellar Expert's ecosystem directory and checked against their issuer accounts on 2026-10-11. Most images came from matching issuer-published `stellar.toml` entries; SHX, yUSDC and USDT0 use Stellar Expert's issuer-bound cached image when the original was unavailable. Native XLM uses CoinGecko's token artwork with its official Stellar identity reference. USDC and EURC use matching original Circle token artwork.

The collection is an image catalog, never a search allowlist or a registry of tradable Testnet assets. Only Circle's independently documented Testnet USDC and EURC have Testnet aliases. Mainnet entries do not become selectable Testnet assets. Recognized unavailable Mainnet identities retain their explicit disabled treatment.

For other classic asset search results, image resolution reads the full issuer's Horizon account on the selected network, validates its `home_domain`, and uses the installed Stellar SDK's HTTPS TOML resolver. Only a `CURRENCIES` entry matching both case-sensitive code and full issuer supplies an image. Account and domain lookups, including unavailable results, share a one-hour query cache. Metadata never delays discovery or selection, changes asset verification, or affects routing. Missing domains, CORS/network failures, invalid/oversized TOML, unsafe image URLs and broken images leave the same-sized fallback. Source references: [Blux useAssets](https://docs.blux.cc/react/hooks/use-assets) and [Stellar SEP-1](https://github.com/stellar/stellar-protocol/blob/master/ecosystem/sep-0001.md).

Route and status boxes reserve a compact, consistent height. No-route results and wallet/funding warnings use the app's yellow semantic treatment; errors use red. The selector search field uses a subtle container focus border, with explicit keyboard focus retained on options.

## Quotes and execution

Quotes debounce for 350 ms and refresh through the SDK's query hook every 30 seconds while visible. Background requests retain the displayed estimate until a new response arrives. Errors and empty paths invalidate it. A nonempty response that fails identity/amount validation reports a quote error, not absent liquidity. SDK query keys isolate pairs and amounts, and request keys also isolate accounts. Refreshes share in-flight requests. Amount inputs retain their original text; displays round to two decimals, and nonzero fees below 0.01 display as <0.01. An empty result uses one compact inline state without a manual refresh control. The Network row remains visible above the inset Transaction details section.

`getStrictSendPaths` resolves the receiving-asset array directly, rather than limiting it to the receiver's existing trustlines. Spot passes `[selectedReceivingAsset]` to [useStrictSendPaths](https://docs.blux.cc/react/hooks/use-strict-send-paths). The native transaction builder adds a missing receiving trustline before the path payment. Direct orderbooks and historical trades do not gate execution; confirmed checks below include indirect paths.

Slippage is stored in integer basis points and applied with integer arithmetic. The local execution helper rechecks that the selected Stellar path remains available and preserves the reviewed minimum, exact assets, amount, account, fee limit and XLM reserves. Blux React owns wallet confirmation and signing. Its public session network is checked before signing; every signing request explicitly pins the network, and the returned signature is verified against that network before submission. The signed transaction body and expiry are checked before broadcasting.

The form starts with XLM to Circle Testnet USDC, an empty Pay value and a real `0.00` placeholder. Empty or cleared amounts never request quotes. Malformed typing and paste are rejected quietly without changing the accepted value or cursor; genuine precision, limit and balance validation remains. Positive amounts support seven decimal places and exact integer arithmetic internally. Asset-code queries are normalized to uppercase while the typed search text, issuer addresses and returned asset identifiers remain unchanged. Clearing or changing assets invalidates old estimates and errors. Transaction details contains minimum received, slippage, quoted output and the network fee limit; the wallet still shows required trustline operations.

Mutation progress, cancellation and failures use React Query's mutation state and callbacks. Only the submitted transaction identity and checked Horizon confirmation are cached for recovery after navigation or a lost response. Success requires a matching, successful ledger transaction. An uncertain submission remains locked until confirmed, failed or proven expired by the ledger. Earn data and flows remain unchanged.

The review dialog aligns prominent pay/receive amounts in two columns, with its direction arrow anchored to the central divider and a compact gap above Route. Very narrow screens stack the summary. Loading and success presentation was recovered from commit `b90b8a7`: the shared blue `signature-request` panel and original compact `transaction-result is-success` row with a green check beside the received amount and confirmation text. Later orbit and success-summary overrides were removed. Current confirmed receipt data, fee, ledger, explorer link and Done action remain. Wallet approval and network confirmation retain distinct states, and the restored spinner stops under reduced motion. Route hops use 28 px original asset icons, grouped icon/code labels and stronger text contrast.

## Configuration and focused checks

Use `NEXT_PUBLIC_STELLAR_NETWORK` with matching public `NEXT_PUBLIC_STELLAR_*` configuration and `NEXT_PUBLIC_BLUX_APP_ID`. Restart development after changing the env. Production and Docker deployments require a rebuild because public env values are bundled at build time. Docker Compose passes the network selection as a build argument. The spot selector explicitly changes networks; endpoint failures never trigger a network fallback. Mainnet API/RPC configuration is described above. No user key is read or stored.

`npm run test:spot`, `npm run lint:spot`, `npm run typecheck`, and `npm run build` check the implementation. `npm run test:spot:browser` covers asset discovery, identity/logo handling, precision, stale requests, quiet refresh, transaction details, errors and mobile keyboard behavior.
